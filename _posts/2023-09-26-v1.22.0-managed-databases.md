sqlc is a command line tool that generates type-safe code from SQL. Today [sqlc v1.22.0](https://docs.sqlc.dev/en/v1.22.0/reference/changelog.html) has been released, let’s take a look at what’s new.

## Managed databases

A few months ago we introduced [`vet`](https://sqlc.dev/posts/2023/07/06/sqlc-one-point-nineteen-released/) to run queries through a set of lint rules. These rules can [prepare queries](https://docs.sqlc.dev/en/v1.22.0/howto/vet.html#sqlc-db-prepare) and [access EXPLAIN output](https://docs.sqlc.dev/en/v1.21.0/howto/vet.html#rules-using-explain-output). Up until now you've needed to have access to a running database to run these rules.

`sqlc` can now create and maintain hosted databases for linting queries in development and CI. PostgreSQL support launches in beta today with MySQL planned for the future. Sign up for access [here](https://docs.google.com/forms/d/e/1FAIpQLSdxoMzJ7rKkBpuez-KyBcPNyckYV-5iMR--FRB7WnhvAmEvKg/viewform).

### Linting queries

With managed databases configured, `sqlc vet` will create a database with your package's schema and use that database when running lint rules that require a database connection, e.g. any [rule relying on `EXPLAIN ...` output](vet.md#rules-using-explain-output).

If you don't yet have any vet rules, the [built-in sqlc/db-prepare rule](vet.md#sqlc-db-prepare) is a good place to start. It prepares each of your queries against the database to ensure the query is valid. Here's a minimal working configuration:

```yaml
version: '2'
cloud:
  project: '<PROJECT_ID>'
sql:
- schema: schema.sql
  queries: query.sql
  engine: postgresql
  database:
    managed: true
  rules:
  - sqlc/db-prepare
```

Set the `project` key in your `cloud` configuration to the value of your project ID obtained via sqlc Cloud. `sqlc` also expects to find a valid auth token in the value of the `SQLC_AUTH_TOKEN` environment variable. See the [managed databases](https://docs.sqlc.dev/en/v1.22.0/howto/managed-databases.html) documentation for a step-by-step guide on setting everything up.

### Verifying test data

We test sqlc against a large suite of [end-to-end integration tests](https://github.com/sqlc-dev/sqlc/tree/main/internal/endtoend/testdata). We're using managed databases ourselves to ensure these tests have valid [database schema](https://github.com/sqlc-dev/sqlc/blob/main/internal/endtoend/ddl_test.go). Each pull requests creates (and drops) around 800 to 1000 databases.

We also exercise example code against live databases. These tests have [been updated](https://github.com/sqlc-dev/sqlc/pull/2749) to use our managed infrastructure. Creating a database for each test ensures each test starts from a clean slate.
